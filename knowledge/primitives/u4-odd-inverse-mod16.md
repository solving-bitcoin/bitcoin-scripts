# Checked odd u4 inverse modulo 16

`arithmetic::u4::odd_inverse::u4_odd_inverse_mod16` range-checks one u4 value,
rejects even values, and selects its multiplicative inverse modulo 16 from a
reusable 16-item table.

## Research question

Can the unit group of `Z/16Z` provide a small reusable checked inverse
primitive for u4-based arithmetic without a two-input multiplication table?
The representative boundary compares one 16-item inverse table with the
256-entry table required by generic modulo-16 multiplication.

## Contract and threat model

The caller pushes `u4_push_odd_inverse_table()` and invokes the query:

```text
preserved | table[16] | odd value -> preserved | table[16] | value^-1 mod 16
```

The query proves the value is numerically in `0..=15` before `OP_PICK` and
rejects even values because their table entries are zero. A numeric range check
does not establish a byte-unique ScriptNum encoding, so callers that need that
property must bind canonical encodings separately.

No witness hints are required. The representative boundary has one data item;
the constant table is generated by the locking script and remains resident
until the caller drops it.

## Comparison and limitations

The construction is useful when an odd nibble must be inverted repeatedly: it
uses 16 table items and rejects non-units, while generic two-input
modulo-16 multiplication uses 256 result entries. It does not replace generic
multiplication or support even values. This is a fragment rather than a
complete locking script; terminal predicates, clean-stack behavior, and any
canonical encoding boundary remain with the caller.

There is no independent cryptographic security claim and no Bitcoin Core
consensus or relay-policy validation. The execution class is `unclassified`.
