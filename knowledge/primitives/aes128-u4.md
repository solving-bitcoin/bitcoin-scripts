# AES-128 over u4 digits

Implements AES-128 encryption for an embedded 128-bit key and a nibble-oriented
witness plaintext.

- **Position:** general standardized block-cipher evaluation using shared u4
  lookup techniques.
- **Evidence:** differentially validated against AES reference vectors.
- **Representative result:** 25,388 script bytes, 33–65 witness bytes, and a
  908-item peak for the documented zero-key configuration.
- **Key envelope:** deterministic zero/FIPS/all-ones profiles measure 25,388 /
  25,449 / 25,520 script bytes with the same 908-item peak.
- **Tradeoff:** close to the stack ceiling and considerably larger than the
  lightweight PRINCEv2 construction.
- **Deployment:** research tapscript fragment; full policy feasibility is not
  claimed.

## Key-schedule boundary

The research question is whether the embedded AES key changes only static byte
cost or also the live stack boundary. The hypothesis was that generation-time
key constants would alter push widths and fused table selection while the
shared lookup memory would keep the execution peak fixed. The comparison uses
the zero key, the FIPS-197 key `00..0f`, and the all-ones key, with identical
32-nibble plaintext witness shape.

The measured policy-produced fragments are 25,388, 25,449, and 25,520 bytes,
respectively; each strict local execution peaks at 908 combined main/alt-stack
items, with 32 data items and zero hints. The generated fragment's static
non-push count is key-dependent as well: 14,375, 14,399, and 14,429 for the
same three profiles. These profiles are differentially checked against the
native AES reference, but they are not an exhaustive search over the 128-bit
key space. Execution remains local tapscript evidence with the combined stack
limit enabled and deployment `unclassified`.
