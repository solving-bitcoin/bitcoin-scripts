# SHA-256 over u32 bytes

Implements SHA-256 using four byte-valued items per word and a shared Boolean
lookup table. It also exposes a one-block continuation for an 80-byte message
and a BIP340-style tagged-hash fragment for a 32-byte payload.

- **Position:** direct byte-oriented construction with representation reuse
  across several local hashes.
- **Evidence:** differentially validated against SHA-256 reference vectors,
  including Bitcoin's genesis header.
- **Representative result:** 512,428 script bytes for a 32-byte hashing
  fragment.
- **Midstate continuation:** the 80-byte continuation consumes 16 byte-valued
  suffix items. The representative fixture is 530,686 script bytes with a
  33-byte serialized witness; the canonical witness maximum is 49 bytes and
  the measured composition peak is 856 stack items. It uses the SHA-256
  640-bit final length field. The caller-supplied state is not
  self-authenticating; prefix binding belongs to the surrounding protocol.
- **Tagged hash:** `sha256_tagged_hash_32bytes` precomputes the BIP340 tag
  block, consumes exactly 32 message items, and continues from that host-side
  midstate with a 768-bit final length. The measured fragment is 530,755
  script bytes with a 65-byte fixture witness, a 97-byte canonical maximum,
  and an 856-item strict composition peak. The tag is generation-time data;
  the fragment does not compute the nonce-and-pubkey BIP340 challenge.
- **Tradeoff:** larger than the measured u4 construction for the same input,
  but interoperates directly with the u32 backend.
- **Deployment:** very large research fragment; strict feasibility must be
  established for each complete composition.
