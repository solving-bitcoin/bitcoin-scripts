# SHA-256 over u4 digits

Implements SHA-256 with two nibble items per byte and optional addition/XOR
tables, including a tracked-stack generator.

- **Position:** smaller measured local SHA-256 script than the u32 backend for a
  32-byte input.
- **Evidence:** differentially validated against SHA-256 reference vectors and
  local cross-implementation tests.
- **Representative result:** 332,942 script bytes for a 32-byte hashing
  fragment; the optimized 80-byte two-chunk profile is 736,595 bytes.
- **Tradeoff:** digit expansion and table choices increase stack-management
  complexity.
- **Output adapter:** `sha256_prefix(num_bytes, output_nibbles)` retains a
  leading digest prefix after the full hash; it does not reduce hash work.
- **Prefix boundary:** the output adapter accepts 1..=64 nibbles; an 8-nibble
  prefix is a 32-bit binding with an ideal 64-bit preimage bound.
- **Representative prefix:** 332,970 bytes, 129-byte witness, 969-item
  research-unlimited peak, and 195,231 static non-push opcodes for 32 bytes.
- **Deployment:** research-oriented; exact table configuration and full stack
  state determine strict feasibility.

## Shared row-offset lookup across chunks

The research question is whether the multi-chunk generator can retain its
16-entry row-offset lookup while replacing only the 136-entry XOR/AND table
between message chunks. The hypothesis is that parking the lookup on the
altstack during that replacement preserves all table offsets and reduces the
locking script for every additional chunk.

The 80-byte two-chunk profile confirms the hypothesis: it is 736,595 bytes,
11 bytes smaller than the prior reload-everything transition. The strict local
run uses 160 complete message-nibble data items, 161 serialized witness bytes,
zero auxiliary hints, a 905-item combined main-plus-alt-stack peak, and
594,466 executed fragment instructions. The cost boundary is
`fragment-only`: message pushes, output cleanup, and the terminal predicate
are excluded from script bytes and fragment opcode counts.

This is `locally-reproduced` and `unclassified` for consensus or relay-policy
deployment. The test vectors cover one- and two-block messages; the optimization
only changes table transport, while the existing SHA-256 differential tests
continue to check the resulting digest. Canonical nibble inputs, padding, and
digest binding remain caller obligations.
