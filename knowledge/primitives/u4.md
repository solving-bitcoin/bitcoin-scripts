# u4 digit arithmetic

Represents values as four-bit stack digits and supplies table-backed addition,
logic, shifts, rotations, batched bit decomposition, and tracked-stack
variants. It is a backend for bit-oriented hashes and block ciphers.

- **Position:** trades more stack items for compact table queries and simple
  nibble semantics.
- **Evidence:** `locally-reproduced` with exhaustive or reference-vector tests for
  core operations.
- **Representative results:** addition-table setup is 92 script bytes. A
  checked 32-nibble decomposition is 924 bytes, contains 735 static non-push opcodes,
  and peaks at 189 combined stack items; the equal-boundary branch baseline is
  1,374 bytes and peaks at 130.
- **Canonical big-endian result:** the canonical-input 32-nibble adapter adds
  raw ScriptNum checks before the same table path and measures 1,306 bytes,
  1,021 non-push opcodes, a 189-item peak, and a 65-byte, 32-item witness
  with zero hint items.
- **Bit-plane result:** the checked 16-nibble transpose reuses the bit table,
  adds a stack permutation, and measures 776 bytes, 573 non-push opcodes, a
  125-item peak, and a 33-byte, 16-item witness with zero hint items.
- **Canonical bit-plane result:** the canonical-input 16-nibble adapter adds
  raw ScriptNum checks before the same transpose and measures 966 bytes, 715
  non-push opcodes, a 125-item peak, and a 33-byte, 16-item witness with zero
  hint items. Its separate metric records the cost of rejecting byte aliases
  rather than treating numeric range checks as canonicality.
- **Canonical little-endian result:** the 32-nibble little-endian adapter adds
  raw ScriptNum validation to the existing 924-byte table path and measures
  1,306 bytes, 1,021 non-push opcodes, a 189-item peak, and a 65-byte,
  32-item witness with zero hint items.
- **Canonical big-endian altstack result:** the canonical-input 32-nibble
  adapter validates raw ScriptNum encodings before the same table path and
  leaves the 128 output bits on altstack for composition; its isolated metric
  records 1,178 bytes, 893 non-push opcodes, a 189-item peak, and a 65-byte,
  32-item witness with zero hint items.
- **Canonical little-endian altstack result:** the canonical-input 32-nibble
  adapter validates raw ScriptNum encodings before the little-endian table path
  and leaves 128 output bits on altstack for composition; its isolated metric
  records 1,178 bytes, 893 non-push opcodes, a 189-item peak, and a 65-byte,
  32-item witness with zero hint items.
- **Bit-reversal result:** the checked 32-nibble adapter is 344 bytes, contains
  232 static non-push opcodes, peaks at 51 combined stack items, and uses a 65-byte,
  32-item witness with zero hint items.
- **Checksum result:** the checked modulo-16 sum of 32 nibbles is 592 bytes,
  uses a 31-item table, peaks at 66 combined items, and returns one numeric
  checksum instead of an output vector.
- **Popcount question:** can a 16-entry nibble table expose Hamming weights
  directly without expanding each nibble into four bit planes?
- **Popcount hypothesis:** a direct checked lookup should preserve the existing
  16-item table shape and be smaller than bit expansion plus per-nibble sums.
- **Popcount boundary:** compare a checked 32-nibble batch with the existing
  bit-plane path, keeping 32 data items, zero hints, table memory, and strict
  output restoration explicit. The direct batch measures 440 bytes and a
  50-item peak, versus 924 bytes and 189 items for bit-plane expansion.
- **Canonical bit-reversal result:** the canonical 32-nibble adapter is 504
  bytes, contains 360 static non-push opcodes, peaks at 51 combined stack
  items, and keeps the same 65-byte witness while rejecting raw aliases.
  The little-endian table matches the big-endian converter's measured boundary
  while emitting each nibble's least-significant bit first.
- **Zero-mask result:** the checked 32-nibble projection is 414 bytes, contains
  318 static non-push opcodes, peaks at 35 combined stack items, and uses a 65-byte,
  32-item witness with zero hint items. It avoids the resident 16-item lookup
  table used by the parity and LSB projections.
- **Packed zero-mask result:** the checked 32-nibble batch is 482 bytes, contains
  382 static non-push opcodes, peaks at 36 combined stack items, and returns four
  byte masks from the same 32-item, 65-byte witness without resident table items.
- **Byte unpack result:** the checked 16-byte unpacker uses a 512-item high/low
  table and measures 1,168 bytes, 546 combined stack items, 544 static
  non-push opcodes, and a 49-byte, 16-item witness. Its standalone bound is
  243 bytes; this is a numeric byte-range check, not raw ScriptNum canonicality.
- **Composition constraint:** table memory and digit-expanded state can dominate
  the 1,000-item stack limit.
- **Unpack comparison:** a fair repeated checked `u8_to_u4_pair(true)` baseline
  is 1,066 bytes and 34 items at 16 bytes, 2,138 bytes and 66 items at 32
  bytes, and 16,275 bytes and 488 items at the 243-byte scalar boundary. The
  table path trades stack occupancy for a smaller repeated-batch script.
- **Input boundary:** the checked decomposition proves numeric range `0..=15`;
  unchecked lookup requires previously certified nibbles and neither form alone
  proves byte-unique ScriptNum encoding.
- **Representation bridge:** checked high/low nibble packing provides a small
  runtime path back to byte-oriented consumers; it is measured separately from
  the table-backed bit decomposition.
- **Representation bridge:** the checked byte splitter uses a four-threshold
  schedule to return high/low nibbles without the 61-item bit-table setup.
  `verify_canonical_nibble()` combines
  the range and raw ScriptNum canonicality checks for hostile witness items.
- **Research question:** can a mirrored staggered table emit least-significant
  bits first without increasing the existing checked converter's script,
  witness, or stack cost?
- **Research question:** does canonical pre-validation make the bit-plane
  transpose safe at a raw-witness boundary while retaining a useful stack
  layout? The comparison is against the 776-byte numeric-range-only transpose;
  the hypothesis is that the adapter preserves semantics and catches aliases,
  at the cost of one canonical boundary per input nibble.
- **Research question:** can the little-endian table decomposition expose its
  useful consumer order at a raw witness boundary without changing its output
  contract? The comparison is against the existing 924-byte numeric-range-only
  path; the hypothesis is that canonical pre-validation catches aliases with
  no hint or stack-growth penalty beyond the boundary schedule.
- **Research question:** can the big-endian table decomposition expose its
  existing output order at a raw witness boundary without changing its stack
  contract? The comparison is against the 924-byte numeric-range-only path;
  the hypothesis is that canonical pre-validation catches aliases with no hint
  or stack-growth penalty beyond the boundary schedule.
- **Research question:** can the big-endian table decomposition expose its
  existing output order on altstack at a raw witness boundary without forcing
  main-stack restoration? The comparison is against the existing checked
  altstack boundary; the hypothesis is that canonical pre-validation catches
  aliases while retaining a composable output schedule.
- **Research question:** can the little-endian table decomposition expose its
  output order on altstack at a raw witness boundary without forcing
  main-stack restoration? The comparison is against the existing checked
  little-endian altstack boundary; the hypothesis is that canonical
  pre-validation catches aliases while retaining a composable output schedule.
- **Hypothesis and comparison:** the mirrored table should match the
  big-endian adapter's 61-item setup, 924-byte 32-nibble fragment, and
  189-item peak, while avoiding a caller-side four-bit reversal composition.
- **Threat model and execution:** witness nibbles are hostile; checked mode
  rejects numeric values outside `0..=15`, but callers still own canonical
  encoding and protocol binding. The result is `locally-reproduced` in the
  repository's strict tapscript executor and remains `unclassified` for
  consensus and policy deployment.
- **Canonical bit-reversal question:** can the existing 16-item reversal table
  bind minimal ScriptNum nibble encodings without changing its output? The
  answer is yes: four-bit reversal is unchanged, canonical validation adds 160
  bytes at the 32-nibble boundary, and the stack peak remains 51 items.
- **Canonical bit-plane threat model and execution:** every input item is
  hostile, including non-minimal or negative ScriptNum encodings. The new
  adapter rejects those encodings before table indexing, preserves surrounding
  main and altstack state, and remains a fragment rather than a complete leaf;
  its result is `locally-reproduced` and `unclassified` for deployment.
- **Canonical little-endian threat model and execution:** every input nibble is
  hostile, including negative, oversized, and non-minimal ScriptNum encodings.
  The adapter rejects them before the lookup table is used and remains
  `locally-reproduced` and `unclassified` for deployment.
- **Canonical big-endian threat model and execution:** every input nibble is
  hostile, including negative, oversized, and non-minimal ScriptNum encodings.
  The adapter rejects them before the lookup table is used and remains
  `locally-reproduced` and `unclassified` for deployment.
- **Canonical big-endian altstack threat model and execution:** every input
  nibble is hostile, including negative, oversized, and non-minimal ScriptNum
  encodings. The adapter rejects them before the lookup table is used, leaves
  its output on altstack for a following fragment, and remains
  `locally-reproduced` and `unclassified` for deployment.
- **Canonical little-endian altstack threat model and execution:** every input
  nibble is hostile, including negative, oversized, and non-minimal ScriptNum
  encodings. The adapter rejects them before lookup, leaves its output on
  altstack for a following fragment, and remains `locally-reproduced` and
  `unclassified` for deployment.
- **Consumers:** u4 SHA-256, AES-128, and PRINCEv2. The little-endian adapter
  targets ScriptNum and scalar consumers that otherwise need per-nibble bit
  reversal.
