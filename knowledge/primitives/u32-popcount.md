# Checked u32 population count

`arithmetic::u32::popcount::u32_popcount` consumes one u32 represented by four
numeric byte limbs and returns the number of set bits. It range-checks each byte
before a 256-entry lookup, then adds the four byte population counts.

- **Input:** `byte[0] | byte[1] | byte[2] | byte[3]`, most significant byte
  first, with the least significant byte on top.
- **Output:** one numeric ScriptNum in `0..=32`.
- **Evidence:** `differentially-validated` by boundary and representative-word
  tests, malformed-byte rejection tests, a strict metric fixture, and one
  complete Taproot spend accepted by Bitcoin Core v30.3.
- **Representative result:** 455 locking-script bytes, 13 serialized witness
  bytes across four `0xff` data items, 262 combined stack items, and no hints.
  The fragment contains 171 static non-push opcodes; this is not an executed
  opcode or deployment claim.
- **Execution class:** `policy-validated` for the exact Core fixture below.
  The strict local executor uses a tapscript context and the combined stack
  limit; the broader fragment remains `unclassified`.

The fixture `u32-popcount-0x12345678` appends `13 OP_EQUAL` to the primitive
and supplies the four data items `12 34 56 78` (most-significant byte first).
It leaves the expected count of 13 and is accepted by both Bitcoin Core v30.3
consensus and its default relay policy. The witness contains four data items
and zero hints. Reproduce it with:

```sh
python3 tools/core_regtest.py --download-core \
  --output target/ci-reports/core-validation-popcount.json
```

This validates one complete transaction, not every 32-bit input or a batched
composition.

The 256-item table is generated by the locking script and removed before the
single result is returned. This is a fragment, so callers still provide any
terminal predicate, clean-stack rule, and byte-unique ScriptNum binding needed
by their protocol.
