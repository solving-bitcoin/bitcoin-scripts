# Checked u4 reflected Gray-code projection

`arithmetic::u4::gray::u4_nibbles_to_gray` consumes canonical u4 nibbles and
maps each value with the reflected Gray-code function:

```text
gray(x) = x XOR (x >> 1)
```

The projection is useful when a downstream state machine wants a compact code
whose consecutive integer values differ in one bit. It is a value transform,
not a cryptographic primitive or a terminal verifier.

## Contract

```text
preserved | nibble[0] ... nibble[n-1]
    -> preserved | gray(nibble[0]) ... gray(nibble[n-1])
```

Every hostile input is checked as `0..=15` before it indexes a generated
16-entry table. The output remains a numeric ScriptNum nibble in `0..=15`, and
the operation preserves the input ordering and surrounding stack state.

## Comparison

Gray projection has the same fixed table and stack profile as the repository's
parity and LSB projections, but returns a full transformed nibble. It is smaller
than expanding each nibble to bits when the consumer only needs Gray-coded
symbols, while a caller that needs the original integer ordering must retain the
documented transform semantics. The table is generated by the locking script;
there are no witness hints or independent security assumptions.

## Validation

Focused tests cover all 16 input values, batch order, malformed nibbles, batch
boundaries, and preservation of unrelated main and altstack items. Run:

```sh
cargo test --locked arithmetic::u4::gray
cargo test --locked --test primitive_metrics u4_gray_metrics_are_current
python3 tools/kb.py validate
```

Execution remains `unclassified`: the local strict executor measures combined
stack occupancy, but no Bitcoin Core consensus or relay-policy transaction has
validated this fragment.
