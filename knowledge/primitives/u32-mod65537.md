# Canonical u32 residue modulo 65,537

## Question, hypothesis and comparison objective

Can a hostile four-byte u32 word be projected to its integer residue modulo
65,537 without hints, a resident table, bit decomposition, or reconstructing an
unsigned 32-bit value in a four-byte ScriptNum? The hypothesis is that two
checked 16-bit lanes and one signed difference beat a general bitwise Horner
remainder circuit under exactly the same canonical-byte input and output
boundary. This is a new local adapter, not a claim of global novelty for the
radix-minus-one modular identity.

## Construction and proof

Let `H=256*b0+b1`, `L=256*b2+b3`, for canonical byte limbs in most-significant
order. Then `word=65536*H+L`, and `65536=-1 (mod65537)`, so:

```text
r = L-H; if r < 0, r += 65537
```

The checked packings produce `H,L` in `0..=65535`. The difference is in
`-65535..=65535`; one addition produces `r` in `0..=65536`. No multiplication
opcode is used: the existing `OP_256MUL()` pseudo-op doubles eight times. Every
intermediate fits the four-byte ScriptNum domain. The entire unsigned 32-bit
word never needs native numeric reconstruction. Notably `0x00010000` returns
65,536, `0x00010001` returns zero, and `0xffffffff` returns zero.

`arithmetic::u32::residue::u32_mod65537()` consumes
`preserved | b0 b1 b2 b3` and returns `preserved | r`. It temporarily parks
byte and lane values above caller altstack state, then restores its own items.
The exact fragment peak is `7+preserved_main+preserved_alt`; all four witness
data items coexist at entry, with **zero hint items** and no table. The output
is one 17-bit numeric ScriptNum, not the four-byte u32 representation. The
caller supplies a terminal predicate and accounts for its resources and cleanup.

## Threat model and evidence

All bytes are hostile, including raw aliases and oversized ScriptNums. The
shared contract suite exercises negative/above-range values, integer overflow,
521-byte elements, malformed values at every position, zero/positive aliases,
short input, asymmetric lanes and runtime preserved state on both stacks.
It independently disables minimal-number policy through the local consensus
profile to prove raw canonicality rejection by the script. Numeric-only
`u32_iszero()` is audited in the same suite and continues to accept permitted
aliases with the correct numeric meaning; no sibling production fix was needed.

The same typed-error assertion fails when the actual compiled canonicality or
range sequences are deliberately removed. Valid controls and output cleanup
use the same harness. Exact resource boundaries pass at 1,000 combined items
and reject one more, for zero, one and three caller altstack items. These are
fragment tests with observable outputs, distinct from complete-leaf acceptance.

Correctness covers each of 256 byte values at every position, all combinations
of eight selected high/low lane boundary values, ten full-word boundaries, and
256 deterministic words. The baseline additionally checks ten boundaries and
128 deterministic words against conventional unsigned host `%65537` arithmetic.
This establishes `locally-reproduced` correctness and resources, without an
independent Script interpreter or full transaction oracle. Deployment remains
`unclassified`. Core arithmetic/resource source is pinned to
[v30.0](https://github.com/bitcoin/bitcoin/blob/d0f6d9953a15d7c7111d46dcb76ab2bb18e5dee3/src/script/interpreter.cpp);
that source inspection does not establish this configuration's acceptance.

## Measurements

Fragment-only: canonical checks, packing and reduction; input pushes and
terminal predicate excluded. Both circuits receive canonical bytes for
`0x89abcdef`, return residue 17,476 and preserve caller state. Witness size
serializes all four data items; it excludes the leaf and control block.
Combined peak is measured with the recorded policy-produced complete leaf
ending in `17476 OP_EQUAL`, which leaves one clean truthy item.

| Construction | Fragment bytes | Leaf bytes | Data witness bytes | Data items | Hint items | Combined peak | Static non-push opcodes |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Two-lane difference | 100 | 104 | 13 | 4 | 0 | 7 | 75 |
| Bitwise Horner baseline | 1,137 | 1,141 | 13 | 4 | 0 | 35 | 684 |

All scripts are below the compilation cutoff and receive `CompileOptions::ALL`
through the repository policy. Dynamic executed-opcode count and complete
transaction validation weight are unavailable; static counts must not be
substituted. No repeated/batched configuration is measured; zero hints per
invocation means this single-word experiment has zero cumulative hint items.
The benchmark and active artifact test bind fragment/leaf/witness SHA256 values,
input word, terminal result, compiler/interpreter pins and execution options.
See the [raw report](../../research/u32-fermat-residue/metrics.json) and
[manifest](../../research/u32-fermat-residue/README.md).

## Comparison and limitations

The two-lane form saves 1,037 fragment bytes and 28 peak items relative to the
same-semantics baseline, without changing witness shape. The baseline is a
useful negative result for this fixed modulus; retain it as comparison-only
code rather than a second public API. See
[the negative result](../negative-results/u32-mod65537-bitwise.md).

Compressed u32 adapters optimize witness width while reconstructing byte words;
this primitive already consumes the four-byte representation and changes its
mathematical codomain, so their sizes are not a dominance comparison. Existing
F257 multiplication likewise has different semantics. Neither a field arithmetic
backend nor a cryptographic checksum/authentication protocol is claimed here.
Words differing by multiples of 65,537 collide, and the caller must bind any
expected residue, input authenticity and length independently.

The 104-byte leaf and its 76 static non-push operations fit the small legacy
resource ceilings, but no bare/P2SH/P2WSH/Taproot transaction or relay policy
acceptance is established. [OP-032](../open-problems.md#op-032--u32-fermat-residue-composition)
requires a pinned complete-leaf differential oracle before stronger claims.

## Reproduction

```sh
cargo test --locked --lib arithmetic::u32::residue
cargo test --locked --test u32_residue_contract
cargo test --locked --test primitive_metrics u32_mod65537_metrics_are_current
cargo run --locked --example u32_fermat_residue_probe
python3 tools/kb.py validate
cargo fmt --all -- --check
CARGO_PROFILE_TEST_OPT_LEVEL=1 cargo test --locked -- --skip fields::
```

The final broad command uses the same host test optimization as CI, retaining
debug assertions and overflow checks. It changes neither Script compilation
policy nor measured bytecode. Compiler is `124b561ed75ac3ec4c6ad99207d8dcdd3bc67180`;
interpreter is `a09e87af444034698697f0a2267e755cf72f9aed`, emitted from the binary's
embedded lockfile by `support::provenance`.
