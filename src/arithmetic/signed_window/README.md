# Signed radix-32 window decoder

This experimental fragment decodes canonical signed ScriptNum digits in
`[-31, 31]` into one native sign bit and five magnitude bits. It is intended
for scalar-window schedulers that already carry signed digits and need a
checked, reusable digit-to-bit bridge.

## Parameters

- Digit domain: canonical ScriptNum `[-31, 31]`.
- Magnitude width: five big-endian bits.
- Batch size: `1..=140` with no unrelated live stack items.
- Auxiliary hints: none.

## Security and execution class

The input digit is hostile witness data. Checked mode rejects non-minimal
ScriptNum encodings, values below `-31`, and values above `31` before using the
magnitude as an `OP_PICK` index. Unchecked mode is only for a caller that has
already established those invariants. The decoder is not a scalar-multiplication
verifier and does not bind digits to a message, point, or signature.

Local tests use the repository's `bitcoin-scriptexec` tapscript helper. The
strict batch test enforces the combined 1,000-item main/alt-stack limit, but no
Bitcoin Core or relay-policy differential validation has been performed; the
execution class is therefore `unclassified`.

## Stack contract

Before a single decode: `preserved | digit | table`.

After: `preserved | table`, with `sign, mag_bit4, mag_bit3, mag_bit2,
mag_bit1, mag_bit0` appended to the altstack. The table is persistent across a
batch and must be dropped after the final digit. Output restoration is the
caller's responsibility.

## Reproduction and comparison

Run the focused tests with:

```sh
cargo test --locked arithmetic::signed_window --lib
cargo test --locked --test primitive_metrics signed_window_metrics_are_current
```

The table wins script bytes only when enough signed digits amortize its 156
items of memory; the branch baseline remains preferable for short or highly
stack-constrained fragments. The measured 32-digit boundary is a local
comparison, not a global optimum claim.
